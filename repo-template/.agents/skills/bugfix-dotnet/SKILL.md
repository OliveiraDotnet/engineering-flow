## Engineering Flow 3.0 execution gate

Follow docs/engineering-flow/workflow.md in the target repository. Understand demand, present a technical plan, receive human approval, implement, execute only approved tests, gather criterion-linked evidence, deliver. Existing explicit authorization persists. Investigation/plan do not authorize implementation. Absence of a test request does not automatically authorize tests: highlight missing validation and ask whether to include it. If only implementation is approved, deliver it as unvalidated with pending checks. Material changes in scope, behavior, architecture/contracts, dependencies, security/data or validation return to the human. This gate governs execution steps below; no automatic delegation or second provider is required.

# Bugfix .NET

1. Read project guidance, `ai-memory` context and confirmed commands. Bootstrap first when the repository map is unverified. Ensure the demand has a card (`AB-<ID>`) and branch (`fix/AB-<ID>-<slug>` from `main`/`master`).
2. Trace the reported behavior to its actual entry point and capture evidence for the failure.
3. Evaluate **legacy test health** for Gate 1: if unit/integration testing is healthy without risky structural refactoring of coupled legacy code, use unit/xUnit integration; if the legacy target is tightly coupled (e.g., Web Forms code-behind, coupled static/session state, classic ASP, or unisolated SQL), do not force invasive refactoring just to create unit tests—escalate `R0` and validation to a **full Playwright E2E test**.
4. `R0` is mandatory for a bug (covered by default in Gate 1). Reproduce the failure first: the regression fails before the fix and passes after. Record both runs. The planner (today, Jeff) gives an opinion before Gate 1. Only Matheus can waive `R0`, explicitly, with the reason written in the plan. Report it when there is no integration test.
5. State the root cause before editing. Keep the fix separate from refactoring.
6. Make the smallest safe change, preserving public behavior outside the defect.
7. Add or update the narrowest healthy regression coverage on the pyramid: unit, xUnit integration, or full Playwright e2e (when legacy code cannot be unit-tested healthily). Playwright, bUnit and Testcontainers are the standard dependencies in the text; the pack does not install them. Use `test-guardian` only if test discovery or design needs independent work. On Trivial, the evidence is a short summary naming the changed file. On Completo, an image is mandatory for a screen criterion, coupled legacy E2E validation, or client evidence, generated by Playwright E2E.
8. Run only confirmed relevant validation commands. .NET Framework 4.8 build and tests are run by Matheus in VS 2022. If unavailable, state the exact blocker and manual validation.

Return root cause, changed files, validation, manual scenario and residual risk.
